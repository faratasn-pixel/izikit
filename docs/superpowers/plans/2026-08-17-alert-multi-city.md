# Alert Multi-City Selection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a user select multiple cities (within one country) when creating a sector alert ("alerte secteur") at `/alertes/new`, and have the alert-matching engine treat any of those cities as a match.

**Architecture:** `Alert.city: String` becomes `Alert.cities: Json` (a `string[]`, following the same JSONB convention already used for `Alert.propertyTypes` — see `matching.ts`'s defensive `Array.isArray` cast). The change ripples through: the Prisma schema + a backfill migration, the `POST/GET /api/alerts` and `GET /api/alerts/[id]` route handlers, the matching engine (`frontend/src/lib/server/alerts/matching.ts`), the shared frontend type (`frontend/src/lib/alerts.ts`), and the create-alert form UI (chip multi-select instead of a `<select>`).

**Tech Stack:** Next.js 16 App Router, Prisma 5 (PostgreSQL/Neon), Zod, Vitest, Tailwind.

**Spec:** [docs/superpowers/specs/2026-08-17-alert-multi-city-design.md](../specs/2026-08-17-alert-multi-city-design.md)

## Global Constraints

- Every Route Handler already has `export const runtime = 'nodejs'` — do not remove it.
- `pnpm format && pnpm lint && pnpm typecheck && pnpm test` must all pass before any commit that isn't itself a WIP checkpoint inside a task.
- Max 10 cities per alert (Zod `.max(10)`) — anti-abuse guard, no deeper business rule.
- One country per alert (unchanged) — only `city` → `cities` changes; `country` stays a single `String`.
- `PropertyRequest.city` is untouched — a property request still has exactly one city.

```sql
-- AlterTable: add cities as nullable first so we can backfill from the old city column
ALTER TABLE "Alert" ADD COLUMN "cities" JSONB;

UPDATE "Alert" SET "cities" = to_jsonb(ARRAY["city"]) WHERE "city" IS NOT NULL;

-- Now that every row has a value, enforce NOT NULL
ALTER TABLE "Alert" ALTER COLUMN "cities" SET NOT NULL;

-- Drop the old single-city column
ALTER TABLE "Alert" DROP COLUMN "city";
```

```typescript
export function matchesAlert(alert: AlertForMatching, request: RequestForMatching): boolean {
  if (alert.transactionType !== request.transactionType) return false;
  if (alert.country !== request.country) return false;
  if (!alertCities(alert).includes(request.city)) return false;
  const propertyTypes = Array.isArray(alert.propertyTypes) ? (alert.propertyTypes as string[]) : [];
  if (!propertyTypes.includes(request.propertyType)) return false;
  if (!priceRangesOverlap(alert.priceMin, alert.priceMax, request.budgetMin, request.budgetMax)) {
    return false;
  }
  return true;
}
```
